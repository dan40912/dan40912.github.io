Implementation Guide

前端重構與落地建議

以下建議不要求推翻現有 demo，而是把目前 HTML、FAQ、external KB 與 Dify DSL 對齊統一 schema、risk gate 與 answer contract。

本頁重點

頁面建議 應抽 JSON Payload Contract 前端 QA
提示 重構優先順序：先讓 payload 穩定，再讓 Dify workflow 穩定，最後才整理視覺細節。金融 demo 最怕看起來漂亮但欄位與風險規則不同步。

頁面建議

index.html

保留對內 / 對外入口與 mock overview。首頁不提供 risk_level、permission_level、approval_required 等手動切換。

HINT首頁只做分流，不做治理決策。

internal/index.html

保留產業卡片、三路線 preset、FAQ、mock profile、payload 複製與 Chatbot 啟動。隱藏 user_type、audit_required、data_policy 等系統欄位。

external/index.html

保留服務卡片、預設問題、轉真人、補充說明、查看進度。不得顯示 internal 欄位、審批細節或 audit log。

風險 HINT對外頁不能出現「主管審批」、「Permission Gate」、「Audit Log」。

internal/call-center/index.html

保留案件列表、高風險卡控、主管批准、回覆客戶、Knowledge Candidate 與 Audit Log。risk label 統一成 normal / medium / high / danger / critical。

前端 QA

  • Internal 與 External payload schema 一致，但顯示欄位不同。
  • External UI 不顯示 internal-only 欄位。
  • 所有高風險 preset 都能帶出 handoff_required=true。
  • 所有 mock data 顯示都標示 demo。
  • 複製 payload 可直接交給 Dify 測試。
  • 所有按鈕都有可見狀態變化，不存在假按鈕。
