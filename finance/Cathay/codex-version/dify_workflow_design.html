Workflow Blueprint

Dify Advanced Chat Workflow

流程採用「先正規化、再分類、先風險、後回答」的設計。對內多 Permission Gate 與 Audit Log；對外則隱藏內部治理，只輸出客戶可理解的安全步驟。

本頁重點

視覺化流程 節點說明 Routing HINT 驗收標準
提示 Dify 裡可以用 LLM node、Question Classifier、Knowledge Retrieval、If/Else 與 Answer node 組成。若 demo 時間有限，先落地 START、Risk Gate、Scenario Router、Internal / External Composer 與 Final Answer。

NLLM
Context Normalizer 整理 user_type、mock data、缺漏欄位

Context Normalizer

職責只整理上下文、不回答問題；核對 user_type / business_line / route_stage 是否合法
OUTknown_facts、missing_fields、normalization_warnings
FALLBACKuser_type 無法辨識 → 預設 external_customer 安全輸出
HINTmock data 只能整理實際存在的欄位，不得說成正式核心系統查詢
CClassifier
Intent Classifier 20 個固定 intent taxonomy

Intent Classifier

職責從固定 taxonomy 選 intent：general_faq、fraud_or_scam、loan_status、human_handoff…
OUTintent、intent_confidence、retrieval_required、handoff_possible
優先要求真人 → human_handoff；詐騙 / 盜刷 / 正在轉帳 → 高風險 intent；明牌 / 保證收益 → investment_advice_boundary
FALLBACK低信心 → insufficient_info
RIF / Gate
Risk Gate 保守上修風險，決定是否轉真人

Risk Gate

職責不因前端傳 normal 而忽略高風險文字，永遠可上修
OUTfinal_risk_level、handoff_required、blocked_content、safe_response_boundary
必升高風險OTP / CVV / 密碼 / 完整卡號、投資明牌、保證收益 / 理賠 / 核貸、詐騙 / 盜刷 / 正在轉帳、對內越權
FALLBACK無法判斷 → medium，要求補充非敏感資訊

Knowledge Retrieval 只讀檢索 FAQ / KB，不外送資料

Knowledge Retrieval

檢索順序同 business_line FAQ → 同 intent KB → user_type 專用 KB → general_finance fallback
OUTretrieved_context、retrieved_sources、retrieval_status
FALLBACK無結果 → no_reliable_context，Final Answer 必須說明依據不足，不得編造
⑂Router
Scenario Router 依 user_type / risk / permission 分流

Scenario Router

路由internal_employee → 對內線；external_customer → 對外線；handoff_required → 交接區；KB 缺口 → Knowledge Candidate
OUTtarget_composer、case_summary_required、audit_log_required
FALLBACK無法判斷 → External Composer 並限制回答
PIF / Gate
Permission Gate 角色、部門、服務關係、資料範圍

Permission Gate（對內）

職責只處理 internal_employee；檢查角色 / 部門 / 服務關係、敏感欄位、是否繞過審批
OUTpermission_status、masked_fields、denied_fields、required_approval_owner
HINT權限不足時不得提供明細，只輸出審批需求與安全摘要；External 不進此節點、也看不到結果
ALLM
Internal Composer Internal Use Only + 客戶可說版本

Internal Answer Composer

職責產生內部回答、mock 現況、下一步與「客戶可說版本」
PROMPT使用 System Prompts 頁的「對內 System Prompt」固定格式
FALLBACK缺權限資訊 → 只列待補欄位與審批建議
LTemplate
Audit Log Composer mock audit log，不含真實個資

Audit Log Composer（對內）

職責為 internal 產生 demo audit log：intent、risk、permission、data_scope、masked_fields
禁止真實個資、正式金額、完整帳號 / 卡號、身分證字號、密碼類資訊
FALLBACK缺欄位 → unknown_demo_value + log_quality=incomplete
ELLM
External Composer 客戶聽得懂的安全步驟

External Answer Composer

職責產生對外六段格式回答與需要補充的非敏感資訊
禁止揭露 Permission Gate、Audit Log、內部審批、模型風險分數；不得索取 OTP / CVV / 密碼 / 完整卡號
FALLBACK資訊不足 → 只追問非敏感必要資訊
HHandoff
Handoff / Case Summary 交給真人客服的去識別化摘要

Handoff / Case Summary Composer

內容問題摘要、已知 mock facts、風險原因、不可索取內容、建議下一步、客戶可見轉接理由
邊界只交出去識別化 / 已遮罩摘要；不含密碼、OTP、CVV、完整卡號 / 帳號 / 身分證字號；不揭露內部權限與 audit log
觸發handoff_required=true 或 risk ∈ high / danger / critical
QLLM
Knowledge Candidate KB 缺口收錄評估，審核後回流

Knowledge Candidate Evaluator

可收錄FAQ 缺口、可泛化 SOP、安全提醒、補件流程、去識別化標準回覆
不可收錄個資、正式金額、案件特定結論、未審核投資建議、內部風控細節
FALLBACK高風險或個資過多 → candidate_status=rejected
✓Answer
Final Answer 最後的對內 / 對外揭露檢查

Final Answer

internal必含 Internal Use Only，可附 mock Audit Log 與客戶可說版本
external不得揭露內部流程 / 權限 / audit log；高風險優先轉真人
全部mock data 只能說是 demo；不得保證收益 / 理賠 / 核貸；KB 無依據不得編造
FALLBACK「目前資訊不足，請補充非敏感資訊；涉及帳戶安全請立即轉真人客服。」

節點位置對應 Dify advanced-chat canvas 的建議擺法；灰色虛線代表非同步 / 附加輸出，紅色代表交接邊界。

節點說明

START

類型：Start

Inputs：完整欄位見 START Schema。

Fallback：缺少核心欄位仍進入 Context Normalizer，由下游標記缺漏。

HINT不要讓 START node 靠使用者文字猜風險。前端至少要帶 user_type、business_line、route_stage、risk_level。
Context Normalizer

類型：LLM

Outputs：normalized_user_type、normalized_business_line、mock_context_available、known_facts、missing_fields。

請只整理上下文，不回答問題。若 mock_data_available=true，只能整理 mock data 實際存在的欄位；缺少的資料要列為 missing_fields。
Intent Classifier

類型：Question Classifier 或 LLM

Outputs：intent、intent_confidence、retrieval_required、handoff_possible。

風險 HINT使用者要求真人、疑似詐騙、盜刷、正在轉帳、不明資金、自傷風險要優先分類成高風險 intent。
Risk Gate

類型：LLM 或 Rule-based Code Node

Outputs：final_risk_level、handoff_required、approval_required、blocked_content、safe_response_boundary。

不得因前端傳 normal 而忽略高風險文字。OTP、CVV、密碼、完整卡號、投資明牌、保證收益、保證理賠、保證核貸、正在轉帳都要上修風險。
Permission Gate（對內）

類型：LLM 或 Rule-based Code Node

Outputs：permission_status、allowed_data_scope、masked_fields、denied_fields、required_approval_owner。

HINT只處理 internal_employee。External 不進這個節點，也不能看見這個節點的結果。
Knowledge Retrieval

類型：Knowledge Retrieval

檢索順序：同 business_line FAQ、同 intent KB、user_type 專用 KB、general_finance fallback。

Fallback：無結果時輸出 retrieval_status=no_reliable_context，不得編造。

Scenario Router 與 Composer

Routing：internal_employee 走 Internal Answer Composer；external_customer 走 External Answer Composer；handoff_required=true 同時產生 Case Summary。

Composer：套用 System Prompts 的固定輸出格式。

Audit Log / Knowledge Candidate / Final Answer

Audit Log：只對 internal 產生 mock JSON，不含真實個資。

Knowledge Candidate：只收錄可泛化、去識別化、已避開金融建議與內部風控細節的內容。

Final Answer：做最後的對內/對外揭露檢查。

Routing HINT

條件路由說明
user_type=internal_employeePermission Gate → Internal Composer必須產生客戶可說版本與 mock Audit Log。
user_type=external_customerExternal Composer不得揭露內部權限、審批、audit log。
risk_level=danger/criticalHandoff / Case Summary優先安全處理，不做一般 FAQ 式回答。
retrieval_status=no_reliable_contextFallback說明知識庫依據不足，不得編造。

Workflow 驗收標準

  • START variables 與 START Schema 完全一致。
  • 所有高風險 intent 都能被 Risk Gate 上修。
  • External Answer 不顯示 Permission Gate、Audit Log、內部審批。
  • Internal Answer 必須產生客戶可說版本與 mock Audit Log。
  • Knowledge Retrieval 無結果時不得編造。
  • Handoff required 時一定產生 case summary。
