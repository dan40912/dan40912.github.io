# elevator-pitch — 把想法變成可播放的短講

貼上文字或加入圖片，快速生成一段約 60 秒、可直接播放的短講，並能下載成**單一 HTML 檔**，離線也能播放。

純 HTML / CSS / Vanilla JS，不需要後端或資料庫，可以直接雙擊 `index.html` 開啟，也可以部署到 GitHub Pages。

## 三個階段

1. **素材**：貼上筆記、文章或口述整理，可再拖入、貼上最多 **5 張圖片**（星號標出主角圖，一句說明能讓配圖更準確）。按「生成我的短講」就好，長度預設 60 秒，觀眾與目的自動判斷；需要時再展開「自訂」。
2. **預覽與微調**：生成時會依序顯示四個步驟；完成後直接進入播放預覽，按「編輯這頁」回到微調。
   - 點投影片上的文字直接修改，點圖片換圖。
   - 每頁的快速操作：**改寫**、**縮短**、**換圖**、**重新生成這頁**，以及排序、複製、刪除。
   - 右側三個分頁：**這一頁**（角色、版型、圖片與焦點）、**講稿**（時間軸、逐頁講稿、一鍵縮短過長講稿）、**整份**（核心觀點、長度、風格、配色）。
   - 復原 / 重做：Ctrl+Z / Ctrl+Shift+Z（游標不在輸入框時）。
3. **播放或下載**：下載單一 HTML、全螢幕播放或排練、製作封面圖，以及 PDF / 簡報檔等其他格式。

## 短講的結構

預設 3–5 頁，每一頁都有自己的角色，不為了湊頁數拆頁：

| 頁 | 角色 | 內容方向 |
| --- | --- | --- |
| 1 | 抓住注意力 | 問題、反差、意外事實或一句鮮明主張 |
| 2 | 建立情境 | 為什麼這件事值得聽 |
| 3 | 傳達核心 | 最重要的觀點或轉變 |
| 4 | 讓想法具體 | 故事、例子、數字或圖片 |
| 5 | 留下記憶 | 結論、一句收尾或明確行動 |

內容簡單時只用三頁（抓住注意力 → 傳達核心 → 留下記憶）。30 秒為 3 頁、90 秒為 4–6 頁，更長的演講會再擴充。

## 單一 HTML 匯出

- 投影片、圖片（內嵌為 data URL）、播放程式都在同一個檔案裡，不依賴原本的網站或帳號。
- 匯出時若有網路，會向 Google Fonts 取得**只包含用到的字**的子集並內嵌，離線開啟字型也一致；若當下離線，則改用系統字型（會在畫面上說明）。
- 播放：方向鍵 / Space / 點擊 / 手機滑動換頁，F 全螢幕，N 顯示講稿（匯出時可選擇是否包含）。網址的 `#3` 會直接跳到第 3 頁。
- 遵循系統的「減少動態效果」設定。

`decks/straight-line-selling.html` 是一份已匯出的範例，可以直接雙擊開啟。

## 三種風格

| 風格 | 視覺 | 圖片怎麼用 | 適合 |
| --- | --- | --- | --- |
| 發表會 Keynote | 黑底、巨大字、一頁一句 | 滿版背景＋深色漸層，播放時緩慢推近 | 產品、募資 |
| 雜誌 Editorial | 米白底、襯線標題 | 右側圖框＋強調色角框 | 品牌故事、個人分享 |
| 數據焦點 Impact | 炭灰底、大數字 | 左半切割，黑白＋強調色雙色調；對比頁放進推薦的一方 | 成果報告、提案 |

每個風格對所有圖片套用同一組裁切與調色，讓隨手拍的照片看起來像同一組作品；每張圖可以再調整焦點。換風格不會改動任何文字。

## 封面

封面以 Canvas 繪製，所見即所得，可直接下載 PNG：16:9（簡報 / YouTube）、1:1（IG 貼文 / LinkedIn）、9:16（限時動態 / Reels）。主句預設取開場那一句；換行優先落在標點；數據焦點風格若有大數字，會一併附上它代表什麼。

## 硬規則與品質審查

- 每頁可見文字 ≤ **100 字**（中文每字算 1，英文單字或數字整串算 1，標點不計；英文簡報為 45 words）。
- 每頁最多 3 個重點 / 步驟。
- 違反硬規則的頁面會標紅，**修正前無法匯出**。「自動精簡與調整」與離線「縮短」都只會刪減，不會新增任何內容。
- 建議類檢查：標題長度、講稿時間是否吻合、相鄰頁版型重複、開場是否空泛、收尾是否有行動呼籲、總時間是否接近目標。

## 生成方式（可替換的 AI 介面）

右上角的齒輪可以切換：

| 模式 | 說明 |
| --- | --- |
| 離線草稿 | 預設。不呼叫任何 AI，只依關鍵詞重組你原文中的句子，**不會產生原文沒有的事實或數據**。「縮短」用規則刪減；「改寫」與「重新生成這頁」需要 AI 代理。 |
| AI 代理端點 | 呼叫你自己部署的代理（範例見 `proxy/`）。API Key 只存在伺服器端。圖片會縮到 1024px 一併送出，讓 AI 看圖配圖。生成後自動審查，不合格就請 AI 重寫一次，最後由本地規則保底。也支援逐頁改寫、縮短、重新生成。 |
| 手動 AI | 一鍵複製完整提示詞，貼到 Claude 等任何 AI 對話，再把回覆的 JSON 貼回來。無法附上圖片本身，AI 只能依你寫的圖片說明配圖。 |

生成失敗時會標出失敗的步驟、保留你的素材，並提供「重試」或「先用離線草稿生成」。

**API Key 永遠不要寫進前端或 GitHub Pages。** 所有 AI 呼叫都在 `js/providers.js`；要接其他服務，用 `Pitch.registerProvider('id', { label, generate(input, onStatus) })` 新增 provider，回傳 `{ deck, fixes }`。`onStatus(step, detail)` 的 step 是 0–3，對應畫面上的四個步驟。提示詞與輸出格式在 `js/prompt.js`。

### 部署 Cloudflare Worker 代理

```bash
cd proxy
npm install @anthropic-ai/sdk wrangler
npx wrangler secret put ANTHROPIC_API_KEY
npx wrangler deploy
```

1. 先把 `proxy/wrangler.toml` 的 `ALLOWED_ORIGINS` 改成你的 GitHub Pages 網址（例如 `https://your-name.github.io`）。
2. 部署完成後，把 Worker 網址填進「生成方式 → AI 代理端點」。

代理使用 `claude-opus-5-5`（effort `medium`），並開啟伺服器端 fallback：模型因安全分類拒答時，會自動改由合適的模型接手。代理只接受白名單網域、限制訊息數量與長度，但 `Origin` 標頭可以被非瀏覽器程式偽造；公開上線時建議再加上 Cloudflare 的 Rate Limiting 規則。

## 部署到 GitHub Pages

1. 把整個資料夾推到 GitHub repository（`proxy/` 也可以一起放，裡面沒有任何金鑰）。
2. Settings → Pages → Source 選 `main` 分支、根目錄 `/`。
3. 開啟 `https://<帳號>.github.io/<repo>/`。

## 本機開發

直接雙擊 `index.html` 即可使用全部功能。若要以伺服器開啟：

```bash
python -m http.server 5173
```

## 檔案結構

```
index.html            介面骨架（素材 / 預覽與微調 / 播放或下載）
css/app.css           生成器介面
js/slides-css.js      投影片樣式（唯一來源；同時注入頁面並內嵌到匯出的 HTML）
js/core.js            資料模型、角色、風格定義、字數計算、工具
js/assets.js          圖片素材（IndexedDB、縮圖）
js/prompt.js          AI 系統提示詞、輸出格式、單頁微調提示詞
js/providers.js       可替換的 AI 介面（local / proxy / manual）與生成步驟
js/engine-local.js    離線草稿引擎
js/qc.js              品質審查、自動修正、離線縮短
js/render.js          投影片渲染（含可直接編輯的欄位標記）
js/cover.js           Canvas 封面繪製與 PNG 匯出
js/export-html.js     單一 HTML 匯出與內嵌播放器
js/present.js         播放模式、計時、講稿
js/demo.js            示範內容
js/app.js             介面控制、微調、復原 / 重做、匯出
proxy/                Cloudflare Worker 代理範例
decks/                範例簡報（.json、匯出的 .html、封面 PNG）
```

資料只存在你的瀏覽器：文字與簡報在 localStorage，圖片在 IndexedDB。只有在使用 AI 代理時，縮小後的圖片才會送到你自己的代理端點。


## 內容生成更新（2026-10-24）

- 共用 `js/content.js` 判斷敘事方向、核心觀點、原文證據與行動邀請；離線判斷屬規則提示，並非 AI 理解。
- AI 依內容選擇邀請、故事、產品或觀點敘事，輸出 `distill.narrative / audienceNeed / action / evidence`，與既有簡報檔相容。
- 內容檢查補上重複主句、遺失行動、視覺用途與預估朗讀時間。這些是可解釋的規則，無法保證事實正確或主觀吸引力。
- AI 最多追加一次修稿，只回傳問題頁；檢查頁碼與格式，並只採用檢查結果改善的版本。其他頁面與圖片配置保留。
- 具視覺能力的代理模式可直接收圖片；離線與手動模式仍需要文字或圖片說明。
- 生成結果分別顯示目標時間、預估朗讀時間。離線生成移除人工等待。
- 本地 JS/CSS 使用版本參數；後續發版請同步更新 `index.html` 版本，避免新 HTML 混用舊程式。


## 名稱與電梯簡報內容方向

專案目錄及產品品牌統一為 `elevator-pitch`，代理套件與部署名稱為 `elevator-pitch-proxy`。既有資料格式中的 `distill`、全域 `Pitch` 與本機儲存鍵保留，以便讀取舊簡報與草稿。既有已匯出的 HTML 屬獨立作品，不隨產品改名而重寫。

參考 [Lado：The Art of the Elevator Pitch](https://www.lado.com.tw/blog/the-art-of-the-elevator-pitch)，加入自我介紹敘事、可驗證的獨特價值，以及能延續對話的結尾。「整份」面板可修改觀眾需求、獨特價值和素材中的下一步。文章提供溝通原則；以下產品設計屬本專案的延伸。

後續優先項目：
1. 開場提供兩到三種候選，使用者可比較，僅重生成開場。
2. 以同一核心內容產生 30／60 秒兩版，保留證據與主要行動；不能只修改每頁秒數。
3. 排練結束提供實際用時、超時頁與可刪段落，不在生成前增加必填設定。
4. 連通真實 AI 後，以產品、自我介紹、活動、知識四組陌生素材評估：理解度、獨特價值、證據、口語自然度、下一步明確度。規則檢查不冒充觀眾評分。

部署注意：更改 Worker 名稱不會自動改名既有雲端服務。若已部署舊代理，舊端點仍需另行遷移；本次只調整本機設定，沒有部署雲端服務。
